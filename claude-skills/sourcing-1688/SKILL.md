## Логика выбора (решения пользователя — не пересматривать)

1. **Откуда товары.** (а) Радар: вещь в тесте → среднечастотные вариации (цвет/фасон/ткань) → запросы по-китайски
   как ищет закупщик — `queries_1688.md` (добавки `一件代发`, `欧美`/`跨境`, `女`, `秋冬`). (б) Пользователь сама
   открывает вкладки 1688 в Chrome (часто через поиск по картинке плагина 1688) — это её выбор.
2. **Её выбор не фильтровать.** Что она открыла/выбрала — в таблицу и в заявки CJ ВСЁ; «подходит/нет» — только пометкой.
   Она сама ставит в колонке «Вердикт» брать / не брать → по команде «убери не брать» удалять строки.
3. **Только поштучно (25.09):** оставлять товары с минимальным заказом 1 шт и с отправкой поштучно (分销代发).
   Минимум 2–3 шт или нет 代发 → убрать из подборки. Проверять СРАЗУ при сборе.
4. **Сезон по названию:** весна-лето = 春夏/春季/夏季 без 秋/冬 → «не наш сезон»; 春秋 — межсезонье, подходит.
5. **Вердикт (мой расчёт, build_catalog.verdict):** брать — ≥$15 чистыми с рекламой и продаж на 1688 ≥50 (юбки) /
   ≥500 (прочее); можно — прибыль есть, но мало продаж или дешевле ¥25; слабо — <$8; не брать — весна-лето,
   аксессуар, копия образа знаменитости, Хэллоуин.
6. **Тренд (плашка, на вердикт НЕ влияет):** тест радара (roll neck, poncho, plaid skirt, bandana cardigan) +
   проверка фасона каждого товара в радаре (`run_word_analysis.py`, источник «товары 1688», слова в
   `fashion-trend-radar/config/words_1688.csv` с колонкой `ru`). Фасон «в кандидаты» → в тренде; «наблюдать» →
   частично; «не проходит» → не в тренде (если тест радара был «в тренде» — частично).
7. **Динамика продаж:** растёт — за 30 дней ≥1,5 среднего месяца года; ровно 0,6–1,5; затухает <0,6;
   новинка — выложен <2 мес.; мало продаж — <20 и за год, и за 30 дней. «<10»=5, «万»=10 000.
8. **Её вкус (подсказка, `taste.py`, колонка «Подсказка по вашему вкусу»; только информирует, не отсеивает).**
   Выведено из её 37 отметок 25.09 и поправок. Ориентир — **тренд-радар**. Плюс: вещь с изюминкой (вышивка, жаккард,
   китайские застёжки-узелки, накидка/пончо, бахрома, ярусы, неровный подол, китайский стиль), новинка (<6 мес.).
   Минус: базовая однотонная вещь, старый затухающий хит (>18 мес.), дороже ¥80, почти нет продаж (<10 за год).
   Нет: юбки мини (только миди/макси), комплекты, облегающие платья, праздничные принты, леопард, капюшон, «Шанель».
   **НЕ критерии (её поправка):** цвет и «кардиган или пуловер». Воротник-бабочка — «не стильно», убран.
   Проверка на её отметках: ни одной грубой ошибки (её «брать» ≠ «скорее нет», её «не брать» ≠ «подходит»).
9. **Правки пользователя в Excel святы.** Её файл не перезаписывать сборщиком с нуля: читать её версию,
   менять только нужные колонки; если файл открыт — сохранять следующей версией `_vN` и сказать. После её
   сортировки в Excel картинки НЕ едут со строками → всегда ставить фото и график заново по ID.
   Если сказала «пока таблицу не меняй» — не трогать до команды.

## Юнит-экономика (по образцу её таблиц «Beauty shop» и «Ремешки»)

- Себестоимость = закупка через CJ (¥ ÷ 7,2 × 1,30) + доставка CJ в США (юбка $6, свитер/кардиган/платье $7,5,
  комплект $8,5, аксессуар $4) + **пошлина США 30% от закупки** (с 29.08.2025 беспошлинный ввоз до $800 отменён;
  уточнить у CJ, не в доставке ли уже).
- С продажи: **Shopify 2,9% + $0,30**, возвраты 5%, чарджбэки 1%, скидка набора 3%, приложения $1,
  **налог с выручки 6%** (УСН «доходы», её ставку уточнить). **Sales tax 5–9%** — платит покупатель, колонка справочная.
- Цена продажи: юбка $65, свитер/кардиган/платье $69, комплект $79, аксессуар $29; себестоимость >$22 → $79.
- Три канала: таргет −CAC $20; блогер 10% с промокода; блогер за видео $50 ÷ 20 продаж. «Лучший канал»,
  оценка «✅ Товар» если лучший ≥ порога ($5, на «Параметрах»). Коэф. розницы, цена у конкурентов (вручную) → индекс к рынку,
  «как поднять средний чек» (наборы −10%, вторая вещь −20%).
- **Уроки из новостей (27.09, её отбор — скилл dropship-lessons):** для каждого товара заранее считать «потолок»
  цены покупателя = цена − себестоимость − доставка − комиссии ($10–15 хорошо, $18–20 в ноль, $25+ дорабатывать);
  закладывать на тест товара $150–300 (≈5 креативов × $30–50), а не $20–30; ROAS ≠ прибыль — считать каждый заказ
  до рекламы и после. При расчёте напомнить ей эти правила одной строкой.

## Грабли

- **openpyxl `delete_rows`/`insert_rows` не сдвигает ссылки в формулах** — после удаления строки запускать
  `refresh_formulas.py` (формулы всех строк по образцу первой). 25.09 из-за этого 4 строки итога считались по соседям.
- Функция TEXT(x,"0.00") в русском Excel даёт #ЗНАЧ! — использовать FIXED(x,2).

- **Динамика 1688 пустая через VPN.** Блок графика и панель помощника работают только при ПРЯМОМ входе на 1688.
  Happ: подписка «Обходы4» — JSON-серверы, профили маршрутизации Happ к ним не применяются
  («Для конфигурации JSON маршрутизация HAPP не применяется»). Решение: копия сервера с правилом
  `{"domain":["domain:1688.com"],"outboundTag":"direct"}` перед финальным правилом → импорт в Happ «+ → из буфера»,
  сервер «1688 напрямую + VPN (#3)». Проверка: `mtop.1688.IpRegionQueryService.queryIpInfo` через `lib.mtop.request`
  на странице 1688 → должен быть Russian Federation. Буфер: класть через `[System.Windows.Forms.Clipboard]::SetText`.
- Прямой вызов `mtop.1688.pc.plugin.od.data.query` без токена расширения → 1006/таймаут — не тратить время.
- **Снимки только при видимой вкладке** (`document.visibilityState=='visible'`): попросить вынести вкладку в
  отдельное окно и не перекрывать. Иначе собирать только текстовые данные, график — вторым проходом.
- Координаты `zoom` зависят от ширины окна (`innerWidth`): при 2160 блок в кадре [275,40,775,410]; перед снимком
  прокрутить к iframe дважды (страница догружается и сдвигает). Ждать `window.context.result` до 12 с.
- Частые графики 1688 режет (пустые нули): 2 товара за заход, при нулях пауза ~1 мин. Проверок «я не робот» при
  таком темпе не было ни разу (64 товара).
- Длинный browser_batch рвёт связь с расширением — 3–4 товара на заход без снимков, 2 со снимками.
- Excel держит открытый файл — сохранять `_vN`; перед записью проверить `[IO.File]::Open(...,'ReadWrite','None')`.
- openpyxl: `insert_cols` не сдвигает формулы, условное форматирование и картинки — переписывать самим;
  ID читать ДО вставки колонок.
- Trends MCP: 100 бесплатных запросов в месяц (в сентябре исчерпаны 25.09).

## Розница → поставщик: Pinduoduo → документы → поиск по фото на 1688 (27.09.2026, её логика)

Смысл: Pinduoduo — **витрина спроса** (что реально выставляют и покупают в Китае); цифры по модели и поставщика
берём на 1688. Шаги:
1. **Выдача PDD** — она сама даёт ссылку поиска `mobile.pinduoduo.com/search_result.html?...` (фасон по-китайски,
   напр. 格子半身裙中长款秋冬, фильтр цены 40–90 ¥). Сбор: `scripts/pdd/pdd_scroll_collect.js` одним запуском
   (медленно, до 60 шагов, сам качает json в «Загрузки») → папка `cj\pddN\pdd_items.json` → оставить только `'裙' in title`
   (или нужный тип) → `pdd_items_skirts.json`. Номера товаров — `pdd_goods_ids.js` → `pdd_ids.txt`.
2. **Таблица с фото**: `ru_pdd.py` в папке поиска (RU {n: перевод по смыслу}, TAGS — см. `ru_pdd_primer.py`),
   `pdd_sheet.py items.json Desktop\pdd_vydachaN.png` (снимок-сетка, фото качаются напрямую), `pdd_table.py`
   (лист с фото, всё по-русски, без столбца «доставка в США»). Все поиски в одну книгу — `svod_pdd.py [имя.xlsx]`
   (список SEARCHES в начале; повторы помечаются; ссылки, где есть pdd_ids.txt).
3. **Модель → документы магазина**: карточка `mobile.yangkeduo.com/goods.html?goods_id=ID`, её ссылка
   `mall_certificates.html?...` (营业执照 картинкой — читать скриншотом): компания, адрес, виды деятельности.
   Офис + «всё подряд» в лицензии = перепродавец; на 1688 его обычно нет (проверка: s.1688.com/company/company_search.htm?keywords=…&charset=utf8).
4. **Поиск по фото на 1688**: `https://s.1688.com/youyuan/index.htm?tab=imageSearch&imageAddress=<URL главного фото PDD>`
   (редиректит на air.1688.com/…/pc-image-search; вкладка должна быть ВИДИМОЙ, иначе пусто). Карточки: offerId, цена,
   «回头率» (доля повторных закупок), «入驻N年», компания; одинаковое китайское название = тот же товар.
5. **Отбор**: её правила — повторные закупки ≥ 60%, с 1 шт, цена 25–65 ¥; сравнить с ценой PDD (наценка розницы).
   **ВНИМАНИЕ (27.09):** «回头率» в карточках поиска/поиска по фото — это доля постоянных покупателей МАГАЗИНА,
   а не модели. Её правило ≥60% — про **复购率 модели** из панели помощника на странице товара (detail.1688.com,
   блок 商品成交趋势情况). Пример: 清野 — 回头率 магазина 63%, а 复购率 юбки 37% → не проходит. Кандидатов из поиска
   по фото отбирать предварительно по 回头率, окончательно — только по 复购率 со страницы товара.
   Фото PDD с img-4.pddpic.com поиск 1688 иногда не видит («空空如也») — заменить хост на img.pddpic.com.
   Понравившегося поставщика она называет «хороший — запомни» → в память (пример: 广州晴雅服装贸易, shop36510729p4205).

Грабли PDD:
- **Продажи почти всегда по магазину**, не по модели: 本店已拼 / 全店总售 = весь магазин, 品牌热销 = бренд,
  已拼/已抢 без «本店» = эта модель, 仅剩 = остаток. **万 = 10 000** (76.6万 = 766 тыс., не 76,6 тыс.!).
- В выдачу подмешиваются чужие рекомендации (еда, техника) — убирать по типу товара.
- «美国不可配送» есть у всех — столбец не нужен (она: «это очевидно»).
- Pinduoduo тормозит подгрузку при быстром листании («正在加载中…» и дальше пусто) — остановиться, не давить;
  между поисками делать паузу. Фото товаров: img-4.pddpic.com имеет медленный адрес — нужен сервер Happ v5
  (память 1688-dinamika-prodazh). PDD/1688/Taobao — в обычном Chrome, не в Dolphin.
- Названия товаров переводить на русский в таблицах PDD она просила; для Taobao/1688 перевод НЕ нужен.
- Фото в таблицы — только когда она просит / после отбора.
